# 保守向け（検査器・終了コード・台帳の所在）

このファイルは道具を作ったり直す人の側の話。使ってグラフを見るだけなら
[README.md](../README.md) と [skill/SKILL.md](../skill/SKILL.md) で足りる。

自動継続ループの運用記録（ラウンドごとの裁定と実測）は `out/loop/protocol.md` に置くが、
`out/` は生成物置き場として追跡しない。**リポジトリに置くべき裁定の記録は
[docs/decisions.md](decisions.md)** に書く。いま進めているゴールと完了条件は
`GOAL.md` に置くが、これは個人の作業台帳として**追跡対象にしない**（`.gitignore` 済み）。

## 見本スクリプト（probe）の置き場所

入出力の見本 2 本（`skill/scripts/probe-doc-links.py` と `skill/scripts/probe-guard-pollution.py`）は
**見張り番の走査対象（`skill/scripts/tools/**/*.py`）の外**に置いてある。走査は走査対象の新しい `import`
に台帳（`guard-owners.json`）への登録を要求するので、見本を内側へ入れると見本 1 本足す毎に人が承認した
台帳を動かす事になる。見本は制御ではなく実演なので、台帳の外に置く。規則の弱体化ではなく置き場所の
決め事で、見本が走査対象から外れている事は `docs/maintenance.md` のこの節が説明する（双人レビューが
人の目で辿る箇所）。

## 回帰バッテリーの置き場所と終了コード（保守向け）

`skill/scripts/tools/battery/` の検査器は、次の 5 つを約束している（第 48 〜 55 ラウンドの
双人レビューで実際に出た事故の形。`out/loop/protocol.md` §4-3 が実行手順）。

- **入力を目の前の `out/tmp-*` から読まない。** `out/tmp-*` はディスク掃除の対象で、消えた日に
  検査が「該当 0 件」で終了 0 になる。追跡下に必要な実体（`baseline-v1` と `graphs/`）を置き、
  `out/` に残すものは作り直しが決まっているもの（`out/demo/graph.json`、`out/perf-inputs/` など）だけにする
- **実行前に所在と中身を点検する。** `python3 skill/scripts/tools/check-battery-inputs.py` が
  道具・固定入力（空 = 0 バイトも不良）・v1 基準 18 条件・追跡下の fixture 19 本・
  検査が足す実グラフの所在と、`input-fingerprints.json` に登録した**入力の指紋 52 件**
  （`out/` 固定入力の構造指紋 + 全入力の SHA-256）の差し替えなしを確かめる（第 52 ラウンド両名 P2
  で件数要求と指紋検査を足し、第 53 ラウンド agy P2 で「無い物と空の一覧を出してから指紋を見る」順に
  直し、第 55 ラウンド Codex 指摘 1 で**中身の指紋**を足した。fixture の `edges` を全部空にする、
  起点にならないノードを 1 つ rename する、のような「構造は同じで中身が違う」差し替えを止める）
- **何を走らせるかを追跡下の一覧で決める。** 回帰検査の起動条件は
  `skill/scripts/tools/battery/required-checks.json`（fixture 19 本 / 219 条件）が正本で、
  `_inputs.launch_conditions()` が組み上げた条件と**中身（`case` / `graph` / `kind` / `args`）が
  一致しない日は測る前に終了 1**。集合だけ・id だけの比較は、中身を書き換えて id を据え置く日を
  通す（第 54 ラウンド Codex 指摘 2）
- **測った件数でも見張る。** 同じ入力で**測る範囲だけが縮んだ日**を入力指紋は止められないので、
  走査した行数・突き合わせた親子数・無方向の行の内訳・`向き` の比較内訳を条件別に
  `required-checks.json` の `expectations` へ追跡下で置き、測ったあとに突き合わせて違えば終了 1
  （`skill/scripts/tools/battery/README.md` に有る測定コマンドで作り直す）
- **無いものと失敗を成功にしない。** 入力が無い・子が失敗したら測る前に終了 1。JSON を書かない
  実行・壊れた JSON・欄の無い JSON・前回の出力をそのまま読む実行は終了 1。比較する行が 0 件なのに
  「違反 0」「1 通りに一致」と出る検査も終了 1（正当な 0 行レポートまで違反にはしない）。
  そして**その検査が実際に落ちることを確かめる道具**が
  `python3 skill/scripts/tools/battery/test-contract.py`。
  制御の本数は実行の末尾に出る。検出できなかった失敗が 1 件でもあれば終了 1
- **見張り番は 1 個ずつ消せる。** 検査器の合否判定はすべて名前を持っていて、
  `CGD_GUARD_OFF=name,name` で任意の名前で見張り番を消せる。`test-contract.py` の負控制は
  **素の実行と、その見張り番を消した実行の 2 度**を走らせ、後者にその案内が出ないことを
  確かめる（別の一の見で落ちるだけの空振りを測らないため。名前のスペル違いもその場で失敗）。見張り番を消すと後が読めない実行系の制御は、**OFF 後も残る別の診断の文面**を `fallback` に宣言させて、その文面以外で落ちたら失敗にする（第 56 ラウンド agy P2-3、第 59 ラウンド Codex P2 で文言を実測へ修正）
  名前は**判定 1 個 = 呼び出し 1 箇所**で付けている。同じ名前を 2 箇所以上で使っていた
  第 59 ラウンドまでは、1 箇所だけを無力化しても他の箇所が生きているので単独名指しの控制が
  通ってしまった（第 59 ラウンド agy P2-3 の 2 の実測、第 60 ラウンド Astra 問 2 の裁定）。
  `test-contract.py` は呼び出し回数も AST で数え、2 箇所以上の名前を失敗にする

## 基盤整備の区切りと保留一覧（Astra 第 76 ラウンド裁定 問 1・問 2）

双人レビューの P2 は 1 ラウンド 2〜4 件で 7 ラウンド続いた。「全 P2 がゼロになるまで続けない」は
探索範囲を広げ続ける限り終了条件にならないので、**次を満たした日に基盤整備を区切る**（Astra の裁定）。

- 保証する入力・台帳・見張り番の網羅・実行器の規則を固定し、その範囲の必須検査が**同じ候補 HEAD** で通る
- P0 / P1 がゼロ。P2 でも、約束した利用範囲での**誤合格・誤拒否・網羅の偽装**につながる再現済みの不具合は解消済み
- 残す改善は下の表へ**影響・保留の理由・再検討の時期** として有限の一覧として書く
- その区切りと保留の一覧を両名のブリーフへ提示し、**同じ HEAD で新たに両名 ACCEPT** を得る

第 80 ラウンドまで双人レビューが 3 ラウンド連続で REQUEST_CHANGES になり、残った指摘がすべて
「文書の案内先の実在」を検査する側の記法解釈と説明文に集中した為、Astra 裁定で**区域を切り直した**
（`docs/maintenance.md` の下表参照）。切り直しの内容:

- 検査 `doc_pointers_resolve` は**固定書式の案内だけ**を見る。コード（バッククォート）で囲まれた
  `skill/…` `docs/…` `demo/…` `README.md` の path の実在。git に無視される物（ビルドで建つ物）は落とさない
- **Markdown の記法は解釈しない**（リンクの宛先、見出しのアンカー、`][`、改行で割れているリンク、
  フェンスとコードの読み分け）。**読めない書き方を理由に落とす**規則もやめる。それは明示した
  必須入力の内側だけで働く規則で、人が普通に書く文書へ適用すると誤検出との付き合い方が目的になる
- 道具の呼び出し例に書いた項目数の文書間一致も外す。件数の保証が必要なら**本体の出力を直接**測る
- 外した保証は下の表へ行として書き、双人レビューの人の目で見る。外した事は見本
  `skill/scripts/probe-doc-links.py` が「測らない対象は通る」実演（20 とおりのうち 10 件）として残す

台帳を細工する負控制（`ledger_owner_moved` など）が**実ツリーの台帳を極短時間だけ書き換えて**
`finally` で戻していた（双人レビュー agy 第 82 ラウンドで原因を特定）。並行して走らせた道具がその瞬間に
台帳を読むと台帳との差分 1 行を拾い、元 bytes がメモリにしか無いのでプロセスが殺されると細工が残る
（次回の通常実行が「所属が変わった」と誤って落ちる）。Astra 第 22 ラウンド 問 3 の裁定は**台帳を書き換える
負控制を通常運用と認めない**事。第 83 ラウンドでは対応表の台帳 1 部だけを逃がしたため、同じ作りが
`required-checks.json`（8 本）・`known-v1-diffs.json`（3 本）・`input-fingerprints.json`（6 本。`finally` で
戻さない）・fixture（2 本）に残っていた（双人レビュー agy 第 83 ラウンド P1。合わせて 19 本）。

今の作りは 2 段にしてある。`stash()` は**使い捨ての repo の写し**を返し（実ツリーは書かない）、細工をする
制御は登録で `shadow=True` を受けて**その写しの中の別プロセス**で走らせる（38 件）。制御が読む台帳・要求
一覧・指紋台帳・fixture はそのプロセスの `__file__` から決まるので、必ず自分の細工と同じ写しを読む。
見張り番の箱 `_inputs.py` へ根の切り替えを足す案は採らなかった — 箱の公開名を 1 つ増やす事は対応表への
登録、つまり人の承認を要求する事なので、第 84 ラウンドで実測して退けた。写しは追跡下の 181 本をコピーし、
`out/`・ビルド済みアナライザ・`.git` は実物から引き継ぐ。うち `out/` は **link ではなくコピー**（link に
すると `.resolve()` が実ツリーのパスを返し、根からの相対で起動条件の key を作る `launch_conditions` が
壊れた。Astra 第 22 ラウンド 問 3 の反例「一時ファイルへ逃がすと本来の配置の検証が通らなくなる」その物）。
測り返しは `ledger_controls_leave_ledger_untouched`（細工の書き先が実ツリーの下に無い事 + 制御の前後で
実ツリーの台帳 4 部と fixture の bytes と**更新時刻**が変わらない事。bytes だけだと「書いて戻す」作りへ
退行しても素通りするので、更新時刻も見る。双人レビュー agy 第 83 ラウンド P2-1 の実測）。

## 検査器の自己検証はこの区域で凍結（決 97）

細工を実ツリーの外へ移す所まで入れて、検査器の検査への追加は打ち切った（双人レビュー 75 本・Astra
相談 20 本で直近 6 ラウンドが全部この区域の中で回っていた為。人の判断は `docs/decisions.md` 決 97）。
**知っている穴**を先に書く。次はどこまで直すかではなく、この区域へ戻るべき日だけ見る:

- 写しへ引き継ぐ `out/` の入力は、battery / tools のソースに書いたリテラルと入力指紋の台帳から集める。
  **実行時に組み立てるパス**（変数の連結）は写しに入らない。入らない場合は「入力が無い」で大きく落ちるので
  素通りはしないが、エラーの意味が遠い
- 写しはコピーした瞬間の版を読む。制御の最中に実ツリーの `out/` を人が差し替えても制御は気づかない
- 制御は 1 本ずつ順番に走る（`out/` など共有する入力があるので並列化していない）
- 戻るべき日: 検査器の穴が実データの誤りとして利用者へ出た日、または人が双人レビューを求めた日

## 段階 H で先に固定する境界（Astra 第 76 ラウンド裁定 問 1）

実装は UI/UX のあとだが、**境界だけ先に決める**（後で UI 側の設計を組み替えないため）。

- **表示文は識別子にしない**。人が読む文面を変えても合否が変わらない様にし、合否は規則と位置で決める
- 診断は**安定した `rule` と `location`** で識別する。`location` は表示の行番号や一時パスに依存させない
- 比較は**重複件数を残す multiset**で行う。集合の比較では同じ規則が 2 件出た日が消える
- 見張り番を消した実行（OFF）と復帰後の実行は、multiset が**一致する**事を求める
